Extract registration metadata from the uploaded scanned property deed.

The PDF may contain 2 or more pages and may use Urdu, Hindi, English, mixed scripts, handwriting, or stamps.

Examine ALL pages before extracting. Use only information supported by the document.

### Page locations
- **Left margin:** Primarily contains handwritten presentation/registration endorsements, party names, relation names, and sometimes property locations.
- **Centre:** Main handwritten register table containing party and property details, including Khata and Khasra numbers. Use it to cross-check marginal entries.
- **Right margin:** Printed vertical page numbers. Extract the first page number as Page No. From and the final page number as Page No. To.

These are typical locations, not fixed positions. Inspect the entire document.

### Extraction rules

1. **Dates:** Extract Presentation Date and Registration Date independently from their respective endorsements. Convert to dd-mm-yyyy. Never copy one date into the other.

2. **Page numbers:** Extract actual printed register page numbers from the first and last PDF pages, not PDF page indices.

3. **Parties:** Identify every Executant (seller/transferor) and Claimant (buyer/transferee). Create a separate entry for every person.

4. **Names:** Transliterate names into English. Exclude titles, honorifics, and addresses.

5. **Relation Name:** Extract the father's or husband's name for each party. Check all pages and repeated references if unclear. Never substitute the person's own name.

6. **Properties:** Extract every property. Create one entry per Khata/Khasra combination. Repeat Khata numbers when multiple Khasra numbers belong to the same Khata.

7. **Locations:** Extract the actual Circle/Anchal and Village/Thana of the property. Do not confuse them with the registration office.

8. **Numbers:** Convert recognizable Urdu/Hindi numerals into digits. Preserve the numbers written in the deed.

9. **Unclear information:** Inspect handwriting, surrounding text, repeated entries, stamps, and other pages. Use the closest defensible reading supported by the document.

10. **No missing-value placeholders:** Never return null, Unknown, N/A, Unreadable, or empty strings. Every field must contain the closest document-supported reading. Never fabricate unrelated values.

### Output

Return ONLY one valid JSON object with exactly these keys and structure. Include all parties and properties.

{
  "Presentation Date": "dd-mm-yyyy",
  "Registration Date": "dd-mm-yyyy",
  "Page No. From": "digits only",
  "Page No. To": "digits only",

    {"Party Type": "Executant", "Name": "...", "Relation Name": "..."},

  ],
  "Properties": [
    {"Circle": "...", "Village/Thana": "...", "Khata No": "...", "Khasra No": "..."}
  ]

Do not add explanations, confidence scores, comments, or additional keys.
